# AGENTS.md

Правила для ИИ-агентов в репозитории **api-docs**: описание API DTF (OpenAPI + проза). Кода приложения здесь нет. Язык — русский, имена полей и путей — как в API.

## Как пользоваться

1. Нужен метод API → откройте `openapi/<область>.yaml` (`auth`, `feed`, `posts`, `comments`, `subsites`, `notifications`, `editor`). Читайте один файл, а не все.
2. Нужны вход, токены, CORS → [docs/auth.md](docs/auth.md).
3. Нужны общие правила (версии, ошибки, пагинация) → [docs/conventions.md](docs/conventions.md).
4. Сомневаетесь, жив ли метод → [docs/status.md](docs/status.md).

## Жёсткие правила

1. **Не выдумывать.** Поле, параметр, код ошибки попадают в спецификацию только если их видели в HAR, в работающем коде reDTF или в живом ответе. Остальное — «не проверено» в `description`.
2. **У каждой операции**: `x-status`, `x-evidence` (`har` / `app` / `probe`), `x-checked` (дата ISO). Меняете описание — обновляйте дату.
3. **Версия в пути** (`/v2.31/feed`) — часть эндпоинта. Одно и то же на другой версии — отдельная операция.
4. **Секреты.** Никаких токенов, кук, почт, телефонов, реальных id и uuid в файлах. Примеры обезличивать. Сырые HAR не копировать сюда и не коммитить (`.gitignore`).
5. **Общее — в `openapi/shared/`.** Схемы не дублировать между областями; `additionalProperties` у ответов не закрывать (сервер отдаёт больше полей, чем мы описали).
6. **Проверка**: `npm run lint` должна проходить без ошибок и предупреждений (настройки в `redocly.yaml`). У каждой операции уникальный `operationId`; публичным методам с необязательным токеном нужен `security: [{}, { JWTAuthorization: [] }]`, методам без токена вовсе — `security: []`.
7. **Запросы к DTF при проверках** — только публичные GET и вызовы без учётных данных. Токены пользователя в запросах не использовать без отдельной просьбы.
